# Trolly Makes Clean Switching Fail Closed

Trolly Agent should implement Clean as a **main-process-owned, fail-closed presentation transaction**: immediately cover every unsafe surface with an opaque native layer and mute all audio, then reveal a preloaded, dressed VRM and neutral agent workspace. It should use **one product GUI**, not two independently operated GUIs or two live VRM scene graphs; a separate safe `WebContentsView` is optional shell isolation, not a second application. Agent chat, MCP calls, and background jobs should continue under their existing consent policy while content labels and epoch checks suppress late images, video, audio, notifications, previews, and restored media. Cold start, crash recovery, sleep/resume, and OS unlock should fail to Clean, with NSFW re-entry requiring a separate deliberate action rather than the panic hotkey. Wardrobe repair should preserve bind-pose data, establish one normalized-rig pose owner, and use validated skinned garments, versioned mesh manifests, and an always-available opaque clean base. DREAM Forge offers useful contracts and product patterns but no working image/video generator to import, and its all-rights-reserved license makes written permission a prerequisite for code reuse. The supplied research found **no standard specific to adult-companion Clean/NSFW switching**; the design below therefore distinguishes adjacent sourced evidence from Trolly-specific engineering recommendations.

**Evidence scope.** Research and source checks were completed **2026-11-12**. Dates below are publication/update dates where the notes recorded them; otherwise they identify living documentation accessed, or repository snapshots reviewed, on 2026-11-12. Within the requested trailing-30-day window, Electron 45 was released **2026-10-21** and Three.js r187 on **2026-10-30**; both are implementation context, not evidence of an adult-companion safety standard or a guaranteed switching latency. ([Electron 45, 2026-10-21](https://www.electronjs.org/blog/electron-45-0); [Three.js r187, 2026-10-30](https://github.com/mrdoob/three.js/releases/tag/r187))

## The main process must own the exposure boundary

**Sourced facts.** GOV.UK’s “Exit this page” pattern immediately displays a blank loading overlay before navigation, providing an established precedent for removing sensitive pixels before slower work completes; its history records introduction in July 2023 and a system-colour overlay update in July 2026. ([GOV.UK guidance and history](https://design-system.service.gov.uk/components/exit-this-page/history/)) Blur serves a different purpose: Instagram places detected nude images behind a reversible warning, while Google Messages explicitly warns that on-device detection can miss content or produce false positives. ([Meta, published 2024-04-11 and updated 2025-06-30](https://about.fb.com/news/2024/04/new-tools-to-help-protect-against-sextortion-and-intimate-image-abuse/); [Google Messages Help, undated, accessed 2026-11-12](https://support.google.com/messages/answer/15724426?hl=en)) Electron’s native `View` supports background colour, visibility, and child ordering, while `WebContentsView` layering is controlled by the main process rather than the page DOM. ([Electron View and web-embed documentation, living, accessed 2026-11-12](https://www.electronjs.org/docs/latest/tutorial/web-embeds/))

**Engineering recommendation.** Make the opaque cover the safety guarantee and the dressed avatar the experience revealed beneath it. A main-process `SafetyController` should own authoritative `mode`, a monotonically increasing `epoch`, native cover/view ordering, window-creation hooks, notification filtering, global activation, and all-page mute. On `enterClean()`, set Clean and increment the epoch, then synchronously request an opaque cover over every window/view and mute every `WebContents`; do **not** await renderer IPC, Vue rendering, asset loading, shader compilation, persistence, media teardown, or cancellation. No fade, translucency, confirmation sound, network request, or safe-asset load belongs in that critical path. If the safe scene cannot be prepared, the cover remains. Electron 45’s reduced overhead for native window/view/web-contents calls is useful context but does not establish a panic-latency guarantee. ([Electron 45, 2026-10-21](https://www.electronjs.org/blog/electron-45-0))

**Trolly should not build two GUIs.** One GUI should bind to the same agent/session/task model and select presentation through the current safety policy: neutral chat and task controls remain usable, while unsafe bodies, prompts, filenames, thumbnails, tool cards, and result previews are withheld. A separate safe `WebContentsView` can reduce renderer trust coupling, but two independent interfaces would duplicate state and create focus, restore, and stale-commit failures without replacing the outer cover. Likewise, a prewarmed second VRM scene can shorten reveal time but adds RAM/VRAM and synchronization risk; prefer one active avatar scene with `cleanRoot` and `adultRoot` under the native gate. VRChat’s substitution of a fallback for blocked, hidden, loading, incompatible, or over-budget avatars is a precedent for safe-avatar substitution, although that document says fallbacks are being deprecated in favour of impostors. ([VRChat Avatar Fallback System, living, accessed 2026-11-12](https://docs.vrchat.com/docs/avatar-fallback-system))

Activation should be **one-way**. A configurable modified global shortcut, visible neutral “Clean view” button, and menu/tray command should all call `enterClean()`, never `toggleMode()`; repeated keys must not expose NSFW. Electron documents that global shortcuts run in main, can fail registration when another application claims them, and return a success value that must be checked. ([Electron `globalShortcut`, living, accessed 2026-11-12](https://www.electronjs.org/docs/latest/api/global-shortcut/)) Provide a separate in-app adult re-entry flow with deliberate confirmation or press-and-hold. Keep an accessible button and programmatic “Clean view on” status, avoid flashes and animated concealment, and test keyboard-only use, screen readers, speech control, Sticky Keys, forced colours, and 200% zoom. WCAG 2.2 supplies relevant character-shortcut, status-message, pause/stop/hide, flash, and interaction-animation criteria, but not companion-specific conformance. ([WCAG 2.2, W3C Recommendation 2024-12-12](https://www.w3.org/TR/WCAG22/))

## Presentation can stop while agent work continues

**Sourced facts.** `AbortController` can cancel fetches, body consumption, and streams, but cancellation does not retract work already completed. `HTMLMediaElement.pause()` controls playback; `AudioContext.suspend()` halts context time and hardware access asynchronously; and Electron’s main-process `webContents.setAudioMuted()` can mute pages enumerated across windows, webviews, and DevTools contents. ([MDN AbortController, modified 2025-09-17](https://developer.mozilla.org/en-US/docs/Web/API/AbortController); [MDN media pause, modified 2023-04-07](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/pause); [MDN AudioContext suspend, modified 2024-10-08](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/suspend); [Electron webContents, living, accessed 2026-11-12](https://www.electronjs.org/docs/latest/api/web-contents/)) Discord says sensitive-media blur applies to historic and new media, a useful precedent for retroactive restore filtering rather than an adult-mode specification. ([Discord Safety Library, living, accessed 2026-11-12](https://discord.com/safety-library))

**Engineering recommendation.** Classify every displayable artifact as `safe | unsafe | unknown`; **unknown is not displayable in Clean**. Apply that classification to avatar layers, poses, animations, textures, images, video, audio, thumbnails, captions, prompts, filenames, notifications, tool results, window/tray titles, popups, and picture-in-picture. Attach `{epoch, contentLabel, taskId}` to every media request and result. After every `await`, worker message, decode callback, texture upload, and IPC reply, re-check main’s current mode and epoch before DOM insertion, canvas drawing, playback, notification, or scene attachment. Stale or unsafe output may be stored under existing data policy but must produce no visible or audible commit. Cancellation is only an optimization; the final presentation gate remains mandatory for producers that ignore abort or finish concurrently.

Do not connect Clean to generic agent cancellation. The scheduler, MCP runtime, conversation turn, checkpoints, and permitted non-visual side effects should continue independently; hide their sensitive presentation and emit neutral status such as “3 tasks running” or “1 result held by Clean view.” If Trolly offers pausing adult media generation, make that a separate media-job policy rather than an implicit property of Clean. Immediately mute all pages first, then pause media and suspend audio contexts without delaying the cover. Route companion TTS and media through a central registry/mixer so no unmanaged element bypasses mute, while keeping playback state separate from task state. Any selectively resumed TTS must be known-safe.

Start cold launches, crash recovery, and restored sessions behind an opaque Clean cover. Restore tasks and data independently, apply the current policy to the entire transcript/media model, and reveal only the filtered view. Treat persisted mode as untrusted: a missing or corrupt preference means Clean. Do not automatically paint the previous NSFW scene after launch, crash, sleep/resume, or Windows unlock; keep the gate up until deliberate adult re-entry. Do not automatically resume previously playing adult audio/video on exit from Clean. Intercept new windows so they also begin covered and muted, and deny unexpected capture requests; Electron 45 routes display/window/tab capture through `display-capture`, which permission handlers must handle explicitly. ([Electron 45, 2026-10-21](https://www.electronjs.org/blog/electron-45-0)) Clean cannot undo an already granted capture, external recording, OS notification history, or observation, so it must not be marketed as anti-forensics or complete privacy.

## Wardrobe repair starts with rig and bind data

**Sourced facts.** VRM uses metres and right-handed Y-up coordinates; its humanoid rest posture is T-pose, with VRM 0.x facing −Z and VRM 1.0 facing +Z. VRM 1.0 permits non-normalized raw bone orientations, while three-vrm’s normalized proxy bones have identity rest orientation. Normalized-to-raw transfer occurs during `vrm.update(delta)`/`humanoid.update()` by default, so direct raw-bone edits can be overwritten. `getNormalizedPose()`/`setNormalizedPose()` use transforms relative to rest T-pose; `normalizedRestPose` is a different, incompatible absolute snapshot. ([VRM features, undated, accessed 2026-11-12](https://vrm.dev/en/vrm/vrm_features/); [three-vrm migration guide, living, accessed 2026-11-12](https://pixiv.github.io/three-vrm/docs/documents/migration-guide-1.0.html#normalized-human-bones); [VRMHumanoid API, living, accessed 2026-11-12](https://pixiv.github.io/three-vrm/docs/classes/three-vrm.VRMHumanoid.html)) Three.js skinning depends on skeleton order, skin indices/weights, bind matrices, and inverse bind matrices; `Object3D.visible` hides an entire subtree but does not dispose resources. ([Three.js SkinnedMesh and Skeleton documentation, living, accessed 2026-11-12](https://threejs.org/docs/pages/SkinnedMesh.html); [Object3D visibility](https://threejs.org/docs/pages/Object3D.html#visible))

**Engineering diagnosis.** The reported T-pose is most consistent with no idle/relaxed pose, a missing `vrm.update()`, normalized auto-update overwriting raw edits, a later animation/wardrobe write, or an accidental rest-pose reset; these are ranked hypotheses, not confirmed root causes because Trolly source, assets, and transform dumps were not supplied. Garment displacement instead points to fixed-proportion offsets, raw-versus-normalized bone confusion, world-versus-bone-local transforms, incompatible bind spaces, wrong inverse matrices/bone order, double root scaling, or incomplete VRM 0.x rotation. Diagnose those before adding offsets: dump VRM version, semantic bone mapping, mesh IDs, skinned status, skeleton UUIDs, bind matrices, and rest/world transforms; render a debug skeleton; and compare representative 0.x and 1.0 assets.

**Engineering repair.** Capture immutable rest transforms and world matrices after loading and `VRMUtils.rotateVRM0(vrm)` once for applicable 0.x models, before garment fitting. Select one animation path and one pose owner. Apply an absolute, named relaxed-arm pose after animation sampling and before `vrm.update(delta)`; do not multiply another rotation onto the current quaternion each frame. Opposite-sign local-Z rotations of normalized upper arms, followed by small lower-arm adjustments, are a reasonable configurable starting preset, but **VRM defines no universal relaxed angle**. Fit garments in controlled rest T-pose, refresh world matrices, then apply the pose. Never rebind meshes, recalculate skeleton inverses, or overwrite bind pose during a clothing toggle.

Use an authored opaque clean bodysuit/base as the fail-closed minimum. Add texture/material variants only for known-compatible UVs and tight designs, and authored `SkinnedMesh` outerwear for silhouette changes; procedural geometry is suitable for simple rigid accessories or a deliberately stylized fallback, not arbitrary torso clothing. Give each avatar a versioned manifest of stable body-region, original-garment, clean-garment, and adult-layer IDs, with each outfit declaring exactly what it shows and masks. Split meshes/primitives at authoring time: hiding an unsplit full-body mesh also hides wanted head/hands, while hiding only a body object can leave separate original clothes visible. Share a skeleton only when garment and target bind spaces are authored compatibly; semantic bone-name remapping alone does not retarget proportions. For clones, use `SkeletonUtils.clone()` and still track shared geometry/material references. ([SkeletonUtils, living, accessed 2026-11-12](https://threejs.org/docs/pages/module-SkeletonUtils.html))

Keep the clean baseline resident and precompile it before the avatar is first exposed; `WebGLRenderer.compileAsync()` is preparation, not something to await during panic. ([Three.js `compileAsync`, living, accessed 2026-11-12](https://threejs.org/docs/pages/WebGLRenderer.html#compileasync)) In the engine’s synchronous mode commit, Clean means `adultRoot.visible === false`, `cleanRoot.visible === true`, and the clean body mask is selected; invalidate pending outfit loads first and reassert this invariant after every load, validation failure, model replacement, and frame setup. Failed or incomplete assets restore the previous known-good clean state. Visibility toggles should not dispose shared resources; use ownership/reference tracking and reserve `VRMUtils.deepDispose()` for wholly owned hierarchies at final unload. ([three-vrm deepDispose implementation, v3.5.5, released 2026-07-09](https://github.com/pixiv/three-vrm/blob/v3.5.5/packages/three-vrm/src/VRMUtils/deepDispose.ts); [Three.js disposal guide, living, accessed 2026-11-12](https://threejs.org/manual/pages/how-to-dispose-of-objects.html)) The researched three-vrm 3.5.5 declares `three >=0.137` but was developed against `^0.180.0`, so r187 satisfies the declared range without proving regression coverage; test actual scenes before upgrading. ([three-vrm 3.5.5 package metadata, 2026-07-09](https://github.com/pixiv/three-vrm/blob/v3.5.5/packages/three-vrm/package.json))

## Delivery should prioritize guarantees before creative breadth

The following sequence is an **engineering recommendation**, not a sourced roadmap. Each gate is testable and keeps creative expansion from weakening the exposure boundary.

| Priority | Deliverable | Acceptance evidence |
|---|---|---|
| **P0 — exposure boundary** | Main-owned `SafetyController`; native covers on every window/view; all-page mute; one-way hotkey/button/menu/tray activation; safe startup and deliberate adult re-entry. | Repeated activation while focused, unfocused, minimized, loading, or with a hung/crashed media renderer produces no unsafe intermediate frame or sound. Registration conflict and safe-asset failure remain covered. |
| **P0 — asynchronous and restored content** | `safe/unsafe/unknown` labels, epochs on every media path, final commit gates, notification/popup/PiP/title filtering, central audio registry, and task-independent presentation filtering. | Race downloads, decode, texture upload, autoplay, worker/IPC completion, VRM swaps, popups, and restore against Clean. Late results stay hidden; task IDs, checkpoints, and permitted MCP effects neither duplicate nor restart; held results remain hidden after relaunch. |
| **P1 — deterministic clean VRM** | Rig/transform diagnostics, one normalized pose owner, rest-pose garment fitting, versioned mesh manifests, opaque clean base, resident/precompiled clean assets, and fail-closed `cleanRoot`/`adultRoot` commits. | Representative VRM 0.x/1.0 models show a dressed, relaxed avatar on the next rendered frame after Clean; late loads cannot expose adult roots; garments track bones through animation without overlap or disposal regressions. |
| **P1 — security and accessibility hardening** | Sender validation, sandbox/context isolation, restrictive CSP, capture-permission denial, focus/status handling, reduced motion, forced-colour support, and latency instrumentation. | Keyboard and assistive-technology tests pass; untrusted content cannot remove the cover; actual cover/mute timings are measured on target hardware. Treat any leaked frame/sound as failure rather than accepting an average latency. ([Electron security checklist, living, accessed 2026-11-12](https://www.electronjs.org/docs/latest/tutorial/security/)) |
| **P2 — approved foundations** | After written permission, extract event/schema, memory/provider, duration/WAV, and audit primitives into main-process services; otherwise implement their behavior clean-room. Add durable provenance and honest statuses. | Schema fixtures, deterministic seed replay, budget/timeout fallback, actual media-duration checks, and failed/partial artifact tests pass; no secret or unsupported success claim reaches the renderer or logs. |
| **P3 — story, design, image, then video** | Original story/character/design contracts first, then real image jobs/review, then shot-based video jobs with probes and export gates. | Every Generate action yields a real artifact or explicit failure, linked to inputs, provider/model versions, safety review, and provenance; no Dreamforge mock output is presented as generation. |

## Conclusion

Clean should be designed as a **durable presentation policy**, not an outfit button or a second application. The critical architectural separation is between task execution and visibility: jobs and continuity remain stable while every output surface independently proves it is safe to reveal. Once that policy and the clean VRM baseline are deterministic, DREAM-derived contracts can accelerate storytelling and media work without coupling creative failure, provider licensing, or asynchronous generation to the panic path. Because the research found no adult-companion-specific standard, quantitative comparison of concealment strategies, universal VRM wardrobe/pose preset, or verified current provider/model terms, Trolly must turn the recommendations above into its own reviewed threat model, asset validation suite, target-hardware measurements, and adult-user accessibility testing.
